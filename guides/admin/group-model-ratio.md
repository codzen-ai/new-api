# 分组模型倍率配置说明

面向管理员。这份文档说明如何给某个分组下的某个模型单独定价，而不影响该分组的其他模型，也不影响其他分组。

终端用户看的文档是 [group-pricing.md](../user/group-pricing.md)。设计文档是 [group-model-ratio.md](../../specifications/group-model-ratio.md)。

## 这个功能解决什么

系统原有的分组定价只有一个粗粒度旋钮：**分组倍率**，它对该分组的所有模型统一打折。
「vip 分组整体八折」能做，「vip 分组的 gpt-4o 单独定价、其他模型不变」做不了。

以前的绕法是克隆一个改名模型（`gpt-4o-vip`）再用渠道重定向指回去。代价是模型列表被污染、
用户看到语义不明的名字、每加一个特价就多一个假模型。

**分组模型倍率**给出第二个维度：按「分组 × 模型」直接定倍率。

## 一条必须先记住的规则

> **配了覆盖，分组倍率对该模型就不生效了。**

举例：全局 `gpt-4o` 倍率 10，vip 分组倍率 0.8。

| 配置 | vip 用 gpt-4o 的最终倍率 |
|---|---|
| 不配覆盖 | 10 × 0.8 = **8** |
| 覆盖 = 5 | **5**（不是 5 × 0.8 = 4，也不是 10 × 0.8 = 8） |

覆盖值就是**最终价**，不是折扣系数。这样设计是因为你想表达的通常是「这个模型在这个分组卖多少钱」，
是个绝对值；如果让分组折扣继续叠加，特价商品又被打八折，几乎总是意料之外的结果。

vip 的其他模型仍然享受 0.8 折扣，只有被覆盖的那个模型不享受。

## 配置步骤

### 1. 进入配置页

**系统设置 → 模型相关设置 → 分组比例（Group ratios）**，点右上角**切换到 JSON**。

分组模型倍率目前只能在 JSON 模式下编辑，可视化编辑器暂无入口。

### 2. 填写 `分组模型倍率`

嵌套 JSON，外层是分组名，内层是模型名到倍率：

```json
{
  "vip": {
    "gpt-4o": 5,
    "claude-3-5-sonnet": 6
  },
  "svip": {
    "gpt-4o": 3
  }
}
```

含义：vip 分组的 `gpt-4o` 最终倍率固定为 5，`claude-3-5-sonnet` 为 6；svip 的 `gpt-4o` 为 3。
两个分组里没列出的模型，照常按 `全局模型倍率 × 分组倍率` 计算。

### 3. 保存

点**保存分组比率**。倍率必须 ≥ 0，负数会被拒绝。

如果这个覆盖是给内部分组、专属分组用的，保存之后还要确认这个分组是不公开的——分组默认并不是私有的，见[让分组不公开](#让分组不公开)。

## 生效范围

只对**按量倍率（按 token）计费**的模型生效。

| 模型的计费方式 | 覆盖是否生效 |
|---|---|
| 按量倍率 | ✅ |
| 固定价（在「模型固定价格」里配了价的） | ❌ |
| 表达式计费（`tiered_expr`） | ❌ |

后两类是**静默失效**：保存成功、界面无报错、计费一点不变。为此后台会在字段下方
列出你配置里那些不会生效的模型名：

> 这些模型按固定价或表达式计费，此处设置的倍率不会生效：draw-model, video-model

看到这条提示说明配错了对象。它只是提示，不会阻止保存——你可能打算先配倍率、之后再改计费方式。

表达式计费的模型要做分组差异化，请在表达式内部处理，或者用分组倍率，不要指望这里。

## 派生价格怎么变

覆盖替换的是**基准价**，其他倍率照常在它上面相乘：

```
输入价 = 覆盖值
输出价 = 覆盖值 × 补全倍率
缓存价 = 覆盖值 × 缓存倍率
```

所以覆盖调整的是这个模型在这个分组的整体价位，输入输出的比价关系不变。
如果需要单独调输出价，当前版本做不到。

## 几个常用配法

### 给某个分组的旗舰模型做特价

```json
{ "vip": { "gpt-4o": 5 } }
```

### 让某个分组免费用某个模型

倍率填 0，会走系统既有的免费模型逻辑（不预扣、不计费）：

```json
{ "internal": { "gpt-4o-mini": 0 } }
```

这种配法通常配合不公开的分组使用，否则所有人都能白嫖，见[让分组不公开](#让分组不公开)。

### 给一个没有全局倍率的模型定价

允许只配覆盖、不配全局倍率。这种模型对配了覆盖的分组是可以正常计费和调用的，
对其他分组则视为未配置价格（用户开启了「接受未设定价格模型」才能用）。

```json
{ "vip": { "some-new-model": 8 } }
```

### 分组之间互不影响

```json
{
  "vip":  { "gpt-4o": 5 },
  "svip": { "gpt-4o": 3 }
}
```

`default` 分组没列出来，它的 `gpt-4o` 仍按 `全局倍率 × default 分组倍率` 算。

## 让分组不公开

**在 `分组比率` 里配了一个分组，不等于这个分组只有你知道。** 分组对谁可见由同一个配置页上的另一张白名单决定：**用户可用分组**（`UserUsableGroups`）。列在这张表里的分组是完全公开的——任何人都能在定价页看到它的倍率（包括未登录的访客），也能在令牌里选中它来用。

这一点对分组模型倍率尤其重要：给某个分组配了内部特价，却把这个分组留在「用户可用分组」里，等于把特价公开挂牌卖。

### 完全私有：只有属于该分组的用户能看见

1. 在 `分组比率` 里给这个分组配一个倍率（**必须配**，见下文）。
2. **不要**把它写进 `用户可用分组`。
3. 在用户管理里，把需要享受这个价格的用户的「分组」直接改成这个分组。

系统会自动把用户自己所属的分组算作可用分组，所以这批用户能正常调用、能在定价页看到覆盖后的价格；其他用户完全看不到这个分组的存在，也无法在令牌里选中它。

例：`internal` 分组的 `gpt-4o` 固定 2 倍率，只有被划入 `internal` 的用户可见。

```json
// 分组比率 GroupRatio —— 必须有条目
{ "default": 1, "internal": 1 }

// 用户可用分组 UserUsableGroups —— 故意不写 internal
{ "default": "默认分组" }

// 分组模型倍率 GroupModelRatio
{ "internal": { "gpt-4o": 2 } }
```

### 定向开放给某几个用户分组

想让「vip 用户也能用这个私有分组」，用 **分组特殊可用分组**（`GroupSpecialUsableGroup`）。外层键是**用户所属的分组**，内层键是要增减的分组，值是展示用的描述：

```json
{ "vip": { "+:internal": "内部特价" } }
```

`+:` 表示追加，`-:` 表示反向屏蔽（把一个公开分组对某个用户分组隐藏），不带前缀等同于追加。这条规则只对 `vip` 用户生效，其他分组的用户不受影响。

### 私有分组仍然要有分组比率

不公开的分组同样必须在 `分组比率` 里有条目。缺条目会导致这个分组无法被令牌选中、也进不了 auto 分组，后台日志还会反复出现 `group ratio not found`。

反过来，`分组比率` 里有条目不代表公开——公开性只看 `用户可用分组`。

### 不公开之后的实际表现

| 位置 | 属于该分组的用户 | 其他用户 |
|---|---|---|
| 模型广场 / 定价接口 | 能看到该分组的分组倍率与覆盖倍率 | 分组本身、分组倍率、覆盖倍率全部不下发 |
| 令牌的分组下拉 | 可选 | 不出现 |
| 令牌指定该分组发请求 | 正常 | 被拒绝 |
| `/v1/models` | 只配了覆盖、没有全局倍率的模型可见 | 该模型不可见 |

## 验证配置

### 看定价页

用属于该分组的账号打开模型广场，找到这个模型，看展示价是否等于覆盖值换算出的价格。
定价页的分组筛选切到具体分组，看到的就是那个分组的价格。

不筛选分组时，模型卡片显示的是该用户**所有可用分组里的最低价**，覆盖会参与这个比较。

### 看账单

发一条请求，然后在日志详情里看倍率：

- `model_ratio` 应等于你配的覆盖值
- `group_ratio` 应等于 `1.00`

`group_ratio` 被归一为 1 就是「覆盖即最终价」在账单上的体现。如果看到 `group_ratio` 还是 0.8，
说明覆盖没命中——检查分组名和模型名是否写对。

### 检查模型是否可见

如果这个模型只有覆盖、没有全局倍率，确认它出现在该分组用户的 `/v1/models` 里：

```bash
curl -s https://你的域名/v1/models -H "Authorization: Bearer sk-xxx" | grep 模型名
```

## 排障

**配了没反应**

按顺序查：

1. 模型是不是固定价或表达式计费？字段下方有没有那条提示。
2. 分组名写对了吗？要写**计费分组**，不是用户分组。用户属于 A 组但令牌指定了 B 组时，
   计费用的是 B 组。
3. 模型名写对了吗？要写系统里的模型名，注意有些模型会做名称归一（比如思考预算变体）。
4. 是不是异步任务模型？提交时预扣、终态时结算，看最终结算后的额度。

**账单比预期贵**

最常见的原因是把覆盖当成了折扣系数。覆盖 5、分组倍率 0.8，最终是 5 不是 4。
想要 4 就直接填 4。

**某个分组的模型突然看不见了**

如果这个模型只有覆盖没有全局倍率，那它只对配了覆盖的分组可见。其他分组的用户看不到它是预期行为。

**不想让所有人看到这个特价**

分组默认是公开的，把它从 `用户可用分组` 里去掉才是私有分组，见[让分组不公开](#让分组不公开)。

**改了配置多久生效**

立即生效，走的是和其他倍率配置一样的热更新通道，不需要重启。

## 与其他分组配置的关系

| 配置 | 作用 | 与覆盖的关系 |
|---|---|---|
| 分组比率（`GroupRatio`） | 分组统一折扣 | 命中覆盖时对该模型失效；私有分组也必须在这里有条目 |
| 用户可用分组（`UserUsableGroups`） | 决定分组对谁可见、可选 | 不影响计费，但决定谁能看到覆盖价 |
| 分组特殊可用分组（`GroupSpecialUsableGroup`） | 按用户分组增减可用分组 | 同上，用于把私有分组定向开放 |
| 分组间覆盖（`GroupGroupRatio`） | A 组用户按 B 组计费时的折扣 | 命中覆盖时对该模型失效 |
| 充值分组比率（`TopupGroupRatio`） | 充值定价 | 无关，不受影响 |
| 模型固定价格（`ModelPrice`） | 按次计费 | 优先级更高，覆盖不生效 |
