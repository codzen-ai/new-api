# 火山方舟 Seedance 官方价格与计费规则

**来源**：火山方舟《模型价格》文档，视频生成模型章节（第 13-18 页）。在线地址 https://docs.volcengine.com/docs/82379/1544106 — 该页面是客户端渲染的，抓取工具只能拿到导航壳，核对时需要在浏览器里打开或导出 PDF。

**核对日期**：2026-07-31（文档内标注的更新时间同为 2026.07.31）。

官方调价后必须同步更新本文件和 `scripts/seedance_billing_check.py` 里的 `OFFICIAL_PRICES`。

## 按 token 单价（在线推理，元/百万 token）

| 模型 | 分辨率档 | 输入不含视频 | 输入包含视频 |
|---|---|---|---|
| `doubao-seedance-2.5` | 480p / 720p | 70.00 | 42.00 |
| `doubao-seedance-2.0` | 480p / 720p | 46.00 | 28.00 |
| `doubao-seedance-2.0` | 1080p | 51.00 | 31.00 |
| `doubao-seedance-2.0` | 4k | 26.00 | 16.00 |
| `doubao-seedance-2.0-fast` | 480p / 720p | 37.00 | 22.00 |
| `doubao-seedance-2.0-mini` | 480p / 720p | 23.00 | 14.00 |

2.0-fast 和 2.0-mini 不支持 1080p 和 4K（官方价格示例表明确标注"不支持"）。2.5 和 2.0-mini 同样只有 480p/720p 档。2.0 系列的离线推理为"暂不支持"。

`doubao-seedance-1.5-pro` 按输出视频是否含声音区分定价：有声 16.00、无声 8.00（离线 8.00 / 4.00）。样片（draft）模式有 token 折算系数：无声 0.7、有声 0.6，其他模型暂不支持折算。

`doubao-seedance-1.0-pro` 15.00，`doubao-seedance-1.0-pro-fast` 4.20。官方价格文档的视频章节没有 `1.0-lite` 条目。

## 计费规则

- **仅对成功生成的视频计费**，因审核等原因导致生成失败不收费。
- `视频价格 = token 单价 × token 用量`
- `token 用量 = (输入视频时长 + 输出视频时长) × 输出视频宽 × 输出视频高 × 输出视频帧率 / 1024`
- **准确 token 用量以调用 API 后返回的 `usage.completion_tokens` 字段为准**（官方在单价说明和最低用量说明中两次强调）。这是本项目实测要验证的第一顺位问题。
- **最低 token 用量限制**：Seedance 2.0 系列和 2.5 在输入包含视频时存在下限，估算用量低于下限则按下限计价。下限与分辨率、宽高比、输出时长有关。因为最终以返回的 `completion_tokens` 为准，网关按该字段计费即自动继承此规则。

注意官方公式里输入视频时长和输出视频时长是相加的，也就是输入视频的开销已经折进同一个 token 数 — 官方并不区分输入 token 和输出 token 的单价，「含视频输入更便宜」是通过降低整体单价实现的，不是通过分项计价。

## 用于公式核对的分辨率参数

按 16:9、帧率 24 fps 推算，5 秒输出视频的 token 用量（无视频输入）：

| 档位 | 宽 × 高 | 5s token 估算 | 官方价格示例（2.0，元/个） |
|---|---|---|---|
| 480p | 864 × 480 | 48,600 | 2.31 |
| 720p | 1280 × 720 | 108,000 | 4.97 |
| 1080p | 1920 × 1080 | 243,000 | 12.39 |
| 4k | 3840 × 2160 | 972,000 | 25.27 |

720p / 1080p / 4K 三档用上表的宽高代入公式，算出的价格与官方价格示例完全一致，说明公式和参数取值正确。480p 有约 3% 偏差（估算 ¥2.24 vs 官方 ¥2.31），推测官方 480p 的实际像素宽高与 864×480 略有不同，所以 480p 档的公式核对要放宽容差。

## 本项目实现的对应关系

价格表在 `relay/channel/task/doubao/constants.go` 的 `videoPriceTable`，存的是绝对单价，计费时取 `实际单价 / 基准价` 作为名为 `video_input` 的 OtherRatio，基准档是零值键 `{480p/720p, 不含视频输入}`。

因此后台配置的「模型倍率」必须等于基准档单价，换算关系：

```
模型倍率 = 官方基准价(元/百万 token) ÷ usd_exchange_rate ÷ 2
```

除以 2 是因为倍率 1 对应 $0.002/1K tokens，即 $2/1M tokens（`common/constants.go` 的 `QuotaPerUnit = 500000`）。
